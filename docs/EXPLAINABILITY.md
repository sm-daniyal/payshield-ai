## 1. The Zero-Hallucination Mandate

In regulated payment systems and dispute arbitrations, post-hoc explanations generated by generative Large Language Models (LLMs) are legally and operationally untrusted:
- LLMs frequently hallucinate plausible-sounding explanations that bear no relationship to the underlying tree activations.
- LLMs can contradict the actual mathematical reasons an order was blocked, creating compliance liabilities under adverse action notification laws (e.g., Equal Credit Opportunity Act, GDPR Article 22).

**PayShield AI implements mathematically grounded feature attribution using `shap.TreeExplainer`.**
Every explanation is extracted directly from the internal decision node pathways of the LightGBM gradient boosted tree ensemble, guaranteed by a cryptographic additivity check.

## 2. Mathematical Additivity Invariant

The fundamental theorem of Shapley values states that the sum of feature attributions across all input signals must exactly equal the difference between the model's prediction and the expected base bias across the training distribution.

### Margin-Space Additivity Formula

For any transaction feature vector $\mathbf{x} = (x_1, x_2, \dots, x_M) \in \mathbb{R}^7$:

$$\phi_0 + \sum_{i=1}^{M} \phi_i(\mathbf{x}) = f(\mathbf{x})$$

Where:
- $\phi_0 = \mathbb{E}[f(X)]$: The base expected value (bias) of the model across the background training distribution.
- $\phi_i(\mathbf{x})$: The exact Shapley contribution of feature $i$ for transaction $\mathbf{x}$, computed via cooperative game theory.
- $f(\mathbf{x})$: The raw, unconstrained margin output (log-odds) of the LightGBM ensemble.

### Platt Sigmoidal Calibration Mapping

Because raw gradient boosted margins are not calibrated probabilities, PayShield AI passes $f(\mathbf{x})$ through a Platt calibration sigmoid:

$$P_{\text{calibrated}}(\text{fraud} \mid \mathbf{x}) = \frac{1}{1 + \exp\left(-\left(A \cdot f(\mathbf{x}) + B\right)\right)}$$

Where parameters $A$ and $B$ are fitted via 5-fold cross-validation (`CalibratedClassifierCV(method="sigmoid", cv=5)`).

### Strict Runtime Additivity Invariant Check

For every live evaluation request processed by `/api/v1/evaluate`, the system verifies:

$$\Delta = \left\lvert \left(\phi_0 + \sum_{i=1}^{M} \phi_i(\mathbf{x})\right) - f(\mathbf{x}) \right\rvert < 10^{-4}$$

```python
# Verification invariant enforced at runtime
delta = abs((base_bias + sum(shap_values)) - raw_prediction_margin)
if delta >= 1e-4:
    raise UncalibratedInferenceError(
        f"Cryptographic additivity check failed: delta={delta:.6f} >= 1e-4"
    )
```

If $\Delta \ge 10^{-4}$, the evaluation fails closed with HTTP 500 and logs an integrity failure to the append-only audit vault. This guarantees that **no hallucinated or corrupted explanation can ever be served to a merchant**.

## 3. The 7-Signal Feature Vector

PayShield AI engineers 7 leakage-safe signals evaluated across the ensemble:

| Feature Name | Description | Positive SHAP ($\phi_i > 0$) | Negative SHAP ($\phi_i < 0$) |
| :--- | :--- | :--- | :--- |
| `amount_zscore` | Normalized divergence from buyer's historical spending mean. | Order value is significantly higher than buyer's historical baseline. | Order value aligns with or is lower than buyer's typical purchases. |
| `velocity_1h` | Number of transactions executed in the preceding 60 minutes. | High-frequency carding burst or enumeration attack. | Normal single purchase; baseline velocity. |
| `velocity_24h` | Number of transactions executed in the preceding 24 hours. | Elevated multi-hour volume spike. | Expected daily transaction volume. |
| `velocity_7d` | Cumulative transaction volume over a rolling 7-day window. | Atypical weekly acceleration. | Stable, established account cadence. |
| `fx_spread` | Divergence between invoice exchange rate and mid-market rate. | Cross-border currency conversion rate arbitrage detected. | Rates conform to institutional mid-market benchmarks. |
| `geo_mismatch` | Binary indicator: shipping country $\neq$ IP-resolved country. | Potential proxy evasion, forwarding address, or stolen account. | Geolocation of IP matches destination delivery country. |
| `account_risk_score` | Composite score derived from account age, verification, disputes. | New, unverified account with prior dispute history. | Established, verified account with zero chargeback history. |

## 4. Directional Attribution & Visualization Protocol

In the PayShield AI UI and API response payloads:

1. **Sign of $\phi_i$:**
   - **$\phi_i > 0$ (Red / Risk Contributor):** Pushes the calibrated probability towards $1.0$ (indicates fraud).
   - **$\phi_i < 0$ (Green / Trust Contributor):** Pushes the calibrated probability towards $0.0$ (indicates legitimacy).

2. **Normalized Percentage Contribution:**
   To render the intuitive waterfall chart for merchants, relative contributions are computed as:
   $$\text{Contribution Pct}_i = \frac{\lvert \phi_i \rvert}{\sum_{j=1}^M \lvert \phi_j \rvert} \times 100\%$$

3. **Deterministic English Grounding:**
   Raw floating-point attributions are converted into auditable plain-language statements via deterministic string templates:
   - Example: `amount_zscore` with $\phi = +0.85 \implies$ *"Transaction amount ($680.00 USD) is 4.25 standard deviations above the buyer's established historical spending baseline."*
   - No generative LLM is used to synthesize these reasons; they are compiled directly from the numerical feature values.
